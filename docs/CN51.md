# Running Inventario on the CN51

Everything below was already checked on the API 17 emulator. The device adds three things the
emulator can't fake: the USB connection, the real scanner (Virtual Wedge), and the Wi-Fi to the
backend. Go top to bottom; each part says what "working" looks like and what to do if it isn't.

## 1. Connect the CN51 to the PC

Already done on the PC: udev rule `/etc/udev/rules.d/51-android.rules` for vendor `067e`, user in
`plugdev`.

1. On the CN51: **Settings → About device**, tap **Build number** 7 times until it says you are a
   developer.
2. **Settings → Developer options → USB debugging**: on.
3. Plug in the USB cable. If the CN51 asks for a USB mode, pick **MTP** or **PTP** (not mass
   storage).
4. On the PC:
   ```sh
   adb devices
   ```
   - `XXXXXXXX  unauthorized` → look at the CN51 screen, tick *Always allow from this computer*,
     tap **OK**, run `adb devices` again.
   - `XXXXXXXX  device` → connected.
   - Nothing listed → try another cable/port (some cables are charge-only), then
     `adb kill-server && adb devices`. Check `lsusb | grep 067e` shows the device.
5. If the emulator is also running, adb sees two devices. Either close the emulator, or add
   `-s <serial>` to adb commands and use `ANDROID_SERIAL=<serial> ./gradlew installDebug`.

## 2. Install and open the app

```sh
./gradlew installDebug
adb logcat -s Inventory AndroidRuntime      # keep this running in a second terminal
```

The app is called **Inventário** (Portuguese) or **Inventory** (English), depending on the CN51's
language. Working: the home screen shows *Nova entrada* / *Estoque* and, at the bottom,
*Dados de demonstração (sem servidor)*.

`INSTALL_FAILED_OLDER_SDK` would mean the device is older than Android 4.2 (API 17); check
*Settings → About device → Android version*.

## 3. Set up the scanner (Virtual Wedge)

The app reads the scanner as a keyboard: the scanner "types" the barcode and a final key. It
accepts **Enter, numpad Enter, Tab, or a newline** as that final key, so most suffix settings work.

On the CN51 open **Intermec Settings** (sometimes under *Settings → Intermec Settings*, or its own
app icon). Names vary a little between firmware versions; look for:

1. **Data Collection → Internal Scanner** (or *Imager*): scanner **enabled**.
2. **Virtual Wedge**: **enabled**. If there is a *Data Intent* / *Broadcast* option, turn it
   **off** (the app doesn't listen for broadcasts yet).
3. **Symbologies**: **EAN-13** and **UPC-A** enabled (grocery barcodes). EAN-8 is useful too.
4. **Data formatting / Postamble / Suffix**: set to **Enter** (`\n`, `<CR>` or `<LF>` all work).
   No prefix.

Test outside the app first: open any text field (e.g. the browser address bar), pull the trigger
on a product. Working: the digits appear and the cursor jumps as if you pressed Enter.

## 4. Test the app on the device

Do these in order. Tick them in `CHECKLIST.md` item 1.7 when they pass.

1. **New session**: no on-screen keyboard pops up; the screen stays on while this screen is open.
2. Scan a product the demo data doesn't know (any real product) → *Novo produto* dialog with its
   barcode. Fill in name, amount per package (`1,5` and `1.5` both work), unit → **Salvar** → a row
   appears.
3. Scan the same product again → the count goes to 2, no dialog.
4. Tap `+` / `−` / the trash icon, then scan again → the scan still arrives (the list must not
   steal the scanner).
5. Press the CN51's **Home** key, reopen the app → *Continuar entrada (N itens)*; open it, same
   list.
6. **Menu** key (or ⋮) → *Cancelar entrada* works; **Enviar** sends and returns home.
7. **Estoque** → the sent products appear; tap one → detail with the history.
8. Type a barcode with the CN51's keypad + Enter on the scanning screen → works the same as a
   scan (handy when a label won't read).

If something is off:

| What you see | What it means / what to do |
|---|---|
| Nothing happens on scan, no `Scanned:` line in logcat | Virtual Wedge off, or the scanner is in Data Intent mode. Test in the browser (part 3). If the browser gets the code but the app doesn't, send me the logcat. |
| Code appears in the log with extra characters (`]E0789...`, `789...X`) | A prefix or symbology identifier is enabled in the wedge settings; turn it off. |
| Every scan adds two packages | The scanner sends two terminators (e.g. `<CR><LF>` plus Enter). Set the suffix to just Enter. |
| On-screen keyboard covers the list | Tell me; the session screen should hide it (`stateAlwaysHidden`), so the CN51 may need a different setting. |
| The trigger also types into another field / opens something | Tell me which key; the app can swallow that key code. |
| Scan while the *Novo produto* dialog is open lands in the Name field | Expected: whatever has focus gets the scan. |

## 5. Connect to the backend (once it exists)

1. The server must be reachable from the CN51's Wi-Fi: same network, and it must listen on the
   LAN address (`0.0.0.0`), not only `localhost`.
2. Find the PC/server IP (`ip addr` on Linux), e.g. `192.168.0.10`, and the port, e.g. `8080`.
3. Quick check from the CN51's browser: `http://192.168.0.10:8080/inventory` should show JSON.
4. In the app: home → **Servidor** (title bar, or the Menu key) → `192.168.0.10:8080` →
   **Salvar**. The bottom line changes to *Servidor: http://192.168.0.10:8080/*.
5. Use **http**, not https: Android 4.2 has TLS 1.2 off by default, so most https servers fail.
6. Back to demo data at any time: **Servidor** → clear the field → **Salvar**.

The endpoints and JSON the backend must implement are in [API.md](API.md). The app was tested
end to end against a fake backend that follows it.

## 6. Sending me what happened

```sh
adb logcat -d > cn51.log                               # everything since the last reboot
adb logcat -d -s Inventory AndroidRuntime > cn51-app.log  # only the app
```

A crash always shows `FATAL EXCEPTION` in `cn51-app.log`. `dalvikvm VFY: unable to resolve ...`
warnings are normal on 4.2; `Verifier rejected class` is not.
